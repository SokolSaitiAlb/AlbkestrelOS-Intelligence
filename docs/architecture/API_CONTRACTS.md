# AIC API Contracts

**Status:** Draft. Interfaces are conceptual until implemented and reviewed.

## Design rules

- Version every public contract.
- Use typed request and response objects.
- Bound string lengths, list sizes, token counts, and execution time.
- Include caller identity and purpose at service boundaries.
- Never accept arbitrary shell commands, class names, Binder descriptors, or filesystem paths from model output.
- Return explicit errors; do not silently broaden permissions.

## Inference contract (conceptual)

```kotlin
interface InferenceEngine {
    suspend fun generate(request: InferenceRequest): InferenceResult
}

data class InferenceRequest(
    val requestId: String,
    val task: InferenceTask,
    val input: String,
    val maxOutputTokens: Int,
    val deadlineMillis: Long
)

data class InferenceResult(
    val requestId: String,
    val output: String,
    val finishReason: FinishReason
)
```

The real implementation must use structured content types rather than accepting unrestricted sensitive context as a plain string.

## Action contract (conceptual)

```kotlin
data class AicActionProposal(
    val actionId: String,
    val actionType: ActionType,
    val parameters: ActionParameters,
    val rationale: String?
)

enum class ActionStatus {
    PROPOSED,
    DENIED,
    AWAITING_CONFIRMATION,
    AUTHORIZED,
    EXECUTING,
    COMPLETED,
    FAILED
}
```

`ActionParameters` must be a sealed or otherwise strongly typed hierarchy. A generic `Map<String, String>` is not sufficient for production authorization.

## Authorization

Authorization must be generated by the trusted policy service after validating caller, user grant, purpose, action parameters, expiry, and confirmation state. The model cannot provide or forge authorization.
